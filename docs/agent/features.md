# Agent Features

This catalog records what each Grida Agent capability does, the outcome it
should preserve, and the limits that affect use. Desktop chat on macOS and
Linux and the headless `grida-agent` host are the supported surfaces; see
[Supported surfaces](#supported-surfaces). Within Desktop, availability also
depends on the selected model connection.

**Present** marks a capability that works as described on the supported
surfaces. **Partial** identifies narrower availability or behavior.
**Deferred** marks a deliberate scope limit. **Open** marks a capability whose
product behavior still needs a decision. Linked guides describe what to do;
linked scenarios and tests record the evidence behind the described behavior.

Saved LAN HTTP model endpoints stay in Desktop settings but cannot run chat; use
an approved HTTPS endpoint or a loopback HTTP endpoint.

| Command execution            | Present on macOS and Linux. Desktop workspace chats run commands in the project under the Default preset: login-shell environment, no network, writes limited to the project and the system temporary folder, and existing `.git` and agent metadata read-only, so the agent can start a repository but not commit to an existing one. A command still running after its short wait, such as a development server, stays with the chat as a numbered process: later turns read its output, type into it or interrupt it, and ending or stopping a turn leaves it running. Stopping it, deleting the chat or quitting ends it; a chat keeps at most 64. Private ACP clients list and stop a chat's processes and receive the list as it changes; the Desktop composer's process list is [untested in the app](../../test/desktop-agent-chat-background-processes.md). Trusted headless hosts select the same capability through a launch profile. Plan withholds the command tools. Windows is deferred. [Permissions](./permissions.md), [confined commands](./clients.md#run-a-confined-command)     | Run programs, including long-running and interactive ones, under scoped native macOS/Linux confinement, with the chat able to read, interrupt and stop what it started. Native Windows is deferred.        | [Execution](../wg/ai/agent/permissions.md#sandbox-levels)                              |
| Scheduled wake-ups           | Partial. Private ACP clients can allow one check-in on an idle Act message or on the first turn of a non-Ultra Act goal. The chat shows its purpose and due time; the check-in can be cancelled, Pause holds delivery, and after a restart its schedule is restored explicitly. Desktop chat does not offer check-ins. The [configuration contract](https://github.com/gridaco/grida/blob/main/crates/grida-agent/docs/rust-config.md) records the reviewed input-limit field and shared inspect/update operations.

## Checking coverage

observation, interruption, recovery, and eventual retention or deletion. Check
its interaction with concurrent work and unavailable dependencies. A missing
answer belongs in the owning contract before another feature label is added.

## Keeping this compact and current

- Update a feature's row in the same change that introduces, changes, or retires
  its user-visible behavior. Elaborate the behavior in the linked document.
- Describe the situation and observable result in product terms. Preserve the
  reason for a surprising rule and the limits that affect use. Keep internal
  functions, storage details, and test procedures in their engineering owners.
- Update current coverage from the real entrypoint and its evidence. Mark a
  feature Available in release documentation only with a named host and release
  plus acceptance evidence. Keep target contracts separate from that claim.
- Give each user-visible capability one row. Implementation choices and internal
  components belong in the engineering documents.
- Keep FAQ answers and guides derived from this catalog and their linked
  behavior contracts. Resolve disagreements in those owners first.
- Automating or retiring a manual test changes its verification method. The
  feature's promise remains in its canonical description until the product
  behavior itself changes.
